Older entries were written as README sections while the game was being built. Newest information is at the top of README.md.

## MG Candy Blast

Match • Blast • Win! — a single-player match-3 candy puzzle game by **MG Cowbell** (MGCowbell / MGTECH), Ghana.
Plain HTML5 + CSS3 + vanilla JavaScript. No frameworks, no paid services, no accounts. Works offline.

## Run it
* **Quick test (easiest on Android):** copy `MG-Candy-Blast-single.html` to the phone and open it in Chrome. Everything is inside that one file.
* **Full project:** serve this folder over HTTP(S), e.g. `python3 -m http.server 8080` then open `http://localhost:8080`. Opening `index.html` directly also works, but the offline cache (service worker) only activates over HTTPS or localhost.

## Files
| File | Purpose |
|---|---|
| `index.html`, `style.css` | Page shell and all styling (buttons, panels, map, modals) |
| `engine.js` | Pure match-3 logic: matches, specials, combos, gravity, shuffle, obstacles |
| `levels.js` | 100 level configurations in 5 worlds |
| `game.js` | Board rendering (canvas), input, animations, boosters, win/lose |
| `ui.js` | Title, level map, settings, daily rewards, profile, tutorial, test menu |
| `art.js` | Procedural candy sprites, backgrounds, logo, mascot |
| `audio.js`, `effects.js`, `storage.js` | Synth sound & music, particles, versioned save data |
| `manifest.json`, `service-worker.js` | Installable web app + offline cache |
| `MG-Candy-Blast-single.html` | All of the above in one file |

Art and sound are generated by code, so `assets/candies`, `assets/backgrounds` and `assets/sounds` only hold notes. `assets/icons` and `assets/images/logo.svg` are real files.

## How to play
Swap neighbouring candies to line up 3+. Match 4 = striped, 5 = color bomb, L/T = wrapped. Swap two specials for bigger blasts. Keyboard: arrows, Enter, keys 1–5 (boosters), Esc (pause).

## Free static hosting
Upload the folder (or just the single file renamed `index.html`) to **GitHub Pages**, **Netlify Drop**, or **Cloudflare Pages**. All give HTTPS for free, which enables offline caching and "Add to Home screen".

## Packaging as an Android app (not done here — no APK was built)
1. Host the game over HTTPS, then use **Bubblewrap** (`npm i -g @bubblewrap/cli`, `bubblewrap init --manifest <url>/manifest.json`, `bubblewrap build`) to make a Trusted Web Activity APK/AAB, **or**
2. Use **Capacitor**: `npm i @capacitor/core @capacitor/cli @capacitor/android`, `npx cap init`, set `webDir` to this folder, `npx cap add android`, `npx cap open android`, build in Android Studio.
Publishing on Google Play needs your own developer account (one-time fee charged by Google).

## Test menu
Open **Settings → About**, tap the logo 5 times (or add `#dev` to the URL). "Enter test mode" copies your save to a sandbox, so unlocking levels, adding coins/boosters, instant win/lose, unlimited lives and sound tests never touch your real progress. "Exit test mode" restores it.

## v1.2 difficulty
Levels 1-5 are gentle (they teach the basics). From level 6 the games use 6 candy colours, fewer moves and higher score/goal targets that keep rising until about level 100, then stay at that hard level forever. Levels show an Easy / Medium / Hard / Very Hard badge. I measured this with two simple bot players (random and greedy, no boosters): early levels are won almost always, levels 40-100 about 30-70% of the time by the greedy bot, and late jelly/chocolate levels are only occasionally won by the bots. Real players can use boosters and plan, so they will do better than the bots. Real-player balance is untested.

## v1.9 CURRENT WIN RULE (replaces v1.5/v1.4 below): stars OR tasks
The level is won as soon as ALL tasks are complete OR the 3-star score is reached, whether or not moves are left (after the current match and cascades finish). If moves reach zero with neither done, the level is failed (Game Over). Stars saved are the stars really earned from the score (1-3); finishing the tasks always gives at least 1 star. Score-only levels have no separate tasks, so they need the 3-star score. To switch back to the stricter 'tasks AND 3 stars' rule change `WIN_RULE='either'` to `'both'` in levels.js.
Also in v1.9: pages restyled to follow the reference sheet more closely (HUD Moves/Target/Pause with the Extra Moves booster as a small badge, 4-booster bar, 'Great Moves!' bar on special events, smooth winding map path with crown on the current level and trees, Level Complete / Game Over / Sound Effects / Boosters / Loading panels). The loading percentage is the real share of start-up steps completed.

## (older) v1.5 THREE-STAR RULE
A level is won only when every goal is finished AND the level's 3-star score (`stars[2]`, shown as "Earn 3 stars: reach N points") is reached. The moment both are true (after the current match and its cascades finish) the level ends, even with moves left. If moves reach 0 first, Game Over shows. Stars are never given for free: 1-2 star scores do not complete a level. Unused moves add a bonus to the final score only after the check. Victory and Game Over can each happen only once, rewards are paid once, and input stops when the level ends.
New in v1.5: voice announcements (Settings: Voice on/off + volume; replaceable files in assets/voice, device speech engine fallback), message system (Sweet!/Great Combo!/Amazing!/Fantastic!/Unbelievable!, New Record!, Achievement Unlocked!, World Unlocked!), new Level Complete / Game Over screens, indeterminate loading screen with rotating messages and Retry on failure, Daily Challenges (real tracked progress, coin rewards), new sounds (level start, coin, world, achievement), sound button on the title screen, centred world buttons / level nodes, responsive status bar.

## v1.7 independent audit (backup of the previous version: backup/MG-Candy-Blast-before-v1.7-audit.zip)
Method: static review of every source file, 1,000+ random taps/drags/keys/resizes across 7 seeds and 5 screen sizes (watching for JS errors, stuck states, board holes, external requests), plus targeted tests. Random-input testing found no crashes; the code review found these real defects, now fixed:
- Life exploit: a life was only deducted when Retry/Home was pressed after Game Over, so closing the app on that screen avoided the penalty. Now deducted when Game Over appears and refunded if +5 Moves is used.
- First-clear reward logic still treated old 1-2 star save entries as "already completed". It now pays once on the first true 3-star clear.
- Android back button left the page. Now: closes dialogs, pauses a level, map -> menu, press twice on the menu to leave.
- No pause when the app goes to the background / a call arrives. A running level now pauses automatically.
- Profile name was only partly escaped when inserted into HTML. Now fully escaped.
- A thrown error inside an animated move could leave the board locked. Moves/boosters are now exception-safe and self-heal; an 8-second watchdog frees input if nothing is animating.
- A fast double tap could start a level twice. Guarded.
- Title screen now shows the coin balance (opens Boosters/Shop).
Not changed (honest notes): the daily reward uses the phone's clock, so changing the clock can claim early (no server to prevent this); this game has no APK build (it is an HTML5 web app); voice is the phone's speech engine unless you add recordings.

## Limitations (please read)
- Voice lines use the phone's speech engine unless you add recordings (see assets/voice/README.txt). That is synthetic speech, not a human recording. No recorded voice or font files could be created or downloaded in my environment, so lettering uses CSS gradients/outlines with system fonts. To add a licensed display font, add an @font-face and put it first in --font in style.css.
- The brief I received stopped mid-way at section 21, so only the parts I could read are implemented.
- This update adds about a dozen real features, not 1,000. Ideas for more are welcome.
- **Not tested on a real Android phone**, no real low-end-device profiling, and offline caching was not verified over HTTPS. Please test on your device.
- The look follows the reference style (glossy candies, dark-blue panels, candy worlds) but is drawn with code, so it is **not a pixel-exact copy** of the image. Fonts: the title font (Lilita One) loads from Google Fonts when online; offline it falls back to a system font.
- Only English is included; the language row is a placeholder for future translations.
- Levels were generated by formula and checked for solvable start boards, but they have not been hand-balanced; difficulty will need tuning.
- No APK has been built and the game is not published anywhere.
- The Privacy Policy is a plain summary, not legally reviewed.
